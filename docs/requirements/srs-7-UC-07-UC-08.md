## 7.x Use Case UC-07

| Use case ID                | UC-07                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Use case name              | Room Schedule View and Booking Request                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Brief description          | A user views the approved bookings of one room on one day. A Borrower who finds a free period submits a booking request for that room, date, time range, headcount and purpose.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Primary actor              | Borrower                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Secondary actors           | Resource Manager and Admin (view the same schedule with requester and purpose; receive the pending request)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Priority                   | Must                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Related requirements       | FR-05-01 to FR-05-06, FR-06-01 to FR-06-09, NFR-02, NFR-03, NFR-10, NFR-11, NFR-12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Trigger                    | The user chooses "Room schedule", or chooses "View schedule" for a room in the catalogue.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Pre-conditions             | 1. The user is signed in (UC-01).<br>2. The room exists in the catalogue (UC-03).<br>3. To submit a request, the user has the Borrower role.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Post-conditions            | Viewing: no data changes. Submitting: a booking request with status Pending is saved for the requester and the room and is visible to the requester and to the Resource Managers of that room. The room is not reserved until approval (UC-08). A failed submit saves nothing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Main flow                  | 1. The Borrower opens the room schedule (S07) and selects a room and a date. The default date is today (UTC+7).<br>2. The system shows the room name, capacity and availability status, the approved bookings of that day in order of start time, and the free periods.<br>3. The Borrower finds a free period and chooses "Request booking".<br>4. The system opens the booking form (S08) with the room and date filled in.<br>5. The Borrower enters the start time, end time, headcount and purpose, and submits.<br>6. The system validates on the server: all fields present; end time later than start time; start time later than now; headcount from 1 to the room capacity; no overlap with an approved booking of the room; room available; user is a Borrower.<br>7. The system saves the request as Pending and shows a confirmation with the request in "My requests" (S10).<br>8. The Resource Managers of the room see the request in "Room requests" (S09).                                                                                                |
| Alternative flows          | A1 (at step 3): The Borrower only wanted to view the schedule and leaves. No request is created.<br>A2 (at step 2): The Borrower selects another room or date. The system reloads the schedule and the flow continues at step 2.<br>A3 (after the failure in E5): The Borrower returns to the schedule, chooses another free period and continues at step 4.<br>A4 (at step 2): A Resource Manager of the room or an Admin opens the schedule. The system also shows the requester and the purpose of each booked slot, and shows no "Request booking" action.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Exception flows            | E1 (at step 2): The room is under maintenance or unavailable. The system shows the status, disables "Request booking" and does not open the form. A request sent directly to the API is rejected and nothing is saved.<br>E2 (at step 6): The headcount is not a whole number of at least 1, or is above the capacity. The system names the field, keeps the entered values and saves nothing.<br>E3 (at step 6): The end time is not later than the start time. Same handling as E2.<br>E4 (at step 6): The start time is not later than the current time. Same handling as E2.<br>E5 (at step 6): The range overlaps an approved booking. The system shows the conflicting slot and saves nothing; see A3.<br>E6 (at step 6): A required field is empty. Same handling as E2.<br>E7 (at any step): The session has expired or the role is wrong. The system returns 401 or 403 and asks the user to sign in again. Entered values are not saved.<br>E8 (at step 7): A system error occurs. The system shows an error, saves no partial request and keeps the form values. |
| Business rules             | Only approved bookings block a room; pending requests do not. Time ranges are half-open, so a booking that ends at 10:00 does not overlap one that starts at 10:00. One request covers one room on one day. A room under maintenance receives no new requests, in the interface and in the backend. All checks run on the server. Times are stored as `timestamptz` and shown in UTC+7. IDs to align with §5.3 (room rules).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Non-functional constraints | Schedule and read calls respond in ≤ 1.0 s at P95 (NFR-01); the submit call in ≤ 2.0 s at P95 (NFR-02). Role and scope are checked on the server for every call (NFR-03). The form works on screens from 360 px wide, by keyboard, with a visible label on every field (NFR-10, NFR-11).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

## 7.x Use Case UC-08

| Field                      | Content                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Use case ID                | UC-08                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Use case name              | Approve and Cancel Room Booking                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Brief description          | A Resource Manager approves or rejects a pending room booking request, and the system blocks an approval that overlaps an approved booking. A Borrower cancels their own booking before its start time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Primary actor              | Resource Manager                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Secondary actors           | Borrower (cancels, sees the result); Admin (may perform every step for any room)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Priority                   | Must                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Related requirements       | FR-07-xx (§5.1 F07 rows, IDs to align), FR-05-03, FR-06-05, FR-06-06, F08 history rows, NFR-02, NFR-03, NFR-09, NFR-11                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Trigger                    | The Resource Manager opens "Room requests". Or the Borrower chooses "Cancel" on a booking in "My requests".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Pre-conditions             | 1. The actor is signed in.<br>2. Approve or reject: the actor is a Resource Manager assigned to the room, or an Admin, and the request is Pending.<br>3. Cancel: the Borrower owns the booking, its status is Pending or Approved, and the current time is before its start time.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Post-conditions            | Approved: the booking blocks the room and appears on the room schedule. Rejected or Cancelled: the booking does not block the room, and a cancelled approved booking disappears from the schedule at once. Every decision is recorded in the history (F08) with actor, time and outcome. After a failure, no status changes.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Main flow                  | 1. The Resource Manager opens "Room requests" (S09). The system lists the pending requests for the manager's assigned rooms (all rooms for an Admin), oldest first.<br>2. The manager selects a request. The system shows requester, room, date, time range, headcount, purpose, and whether the range overlaps an approved booking.<br>3. The manager chooses "Approve".<br>4. In one transaction the system re-checks that the request is still Pending, the start time is still in the future, the room is available, and no approved booking of the room overlaps the range.<br>5. The system sets the status to Approved and records the event in the history.<br>6. The system shows the confirmation. The booking appears on the room schedule (F05) and the requester sees "Approved" in "My requests".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Alternative flows          | A1 (at step 3): The manager chooses "Reject" and may enter a reason **(assumption: optional reason)**. The status becomes Rejected, the event is recorded, and the requester sees "Rejected".<br>A2 (before the start time): The Borrower opens "My requests" (S10), chooses "Cancel" on a Pending or Approved booking and confirms. The system checks the start time, sets the status to Cancelled, releases the time slot, removes the booking from the schedule at once and records the event.<br>A3 (at step 1): An Admin performs the flow for any room.<br>A4 (at step 2): The request is hidden or refused for a manager who is not assigned to the room (see E5).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Exception flows            | E1 (at step 4): The range overlaps an approved booking, for example because another manager approved first. The system refuses the approval, keeps the request Pending and shows the conflicting slot. The manager may reject the request or ask the requester to choose another time outside the system.<br>E2 (at step 4): The start time has passed. The system refuses the approval; the manager may reject the request. **(assumption: the system does not expire the request by itself)**<br>E3 (at step 4): The room is under maintenance or unavailable. The system refuses the approval and shows the reason. **(assumption: PA1 blocks only new requests and leaves approved bookings to be handled outside the system; the team must decide this case)**<br>E4 (at A2): The current time is at or after the start time. The system refuses the cancellation and shows "Cannot cancel after the start time".<br>E5 (at step 1 or 3): The actor is not allowed for the room or the booking. The system returns 403 and changes nothing.<br>E6 (at step 3 or A2): The request was already processed by someone else. The system says so, refreshes the list and changes nothing.<br>E7 (at any step): The session has expired or a system error occurs. The system asks the user to sign in again or shows an error. No partial change is saved. |
| Business rules             | Two approved bookings of the same room must never overlap; the database enforces this and the check runs again at approval. Time ranges are half-open. Only a Pending request can be approved or rejected. A booking can be cancelled only before its start time, and only by its Borrower. A Resource Manager acts only on assigned rooms; an Admin acts on all rooms. Every status change is recorded with actor, time and outcome. Times are shown in UTC+7. IDs to align with §5.3 and the F07 rows.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Non-functional constraints | Approve, reject and cancel respond in ≤ 2.0 s at P95 (NFR-02). With 20 concurrent conflicting approvals, at most one succeeds and no overlap remains (NFR-09). Role and scope are checked on the server (NFR-03). Actions are reachable by keyboard, with labelled controls and a confirmation before cancellation (NFR-11).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |

Open points for the team:

1. E3 (UC-08): can a manager approve a pending request for a room that has since gone under maintenance? PA1 is silent. The draft refuses the approval.
2. E2 (UC-08): should a pending request whose start time has passed expire automatically? The draft does not.
3. Can a Resource Manager or an Admin cancel an approved booking on a Borrower's behalf? PA1 lets only Borrowers cancel; the draft follows PA1.

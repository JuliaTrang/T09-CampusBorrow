# 4.3 Class Specifications (#53)

Eight key classes from [CD-01 and CD-02](4.2-class-diagram.md) are specified in full; two supporting classes (SessionGuard and TimetableService) are summarised at the end. All signatures and types are **proposals**, not approved API or code; the open points in the [README](README.md) apply to every class. `Resource` is an abstract class with `Equipment` and `Room` as subclasses (kickoff glossary); no other class has a superclass. Following ADR-004, `EquipmentRequest` and `RoomBooking` have an integer `version`. Updates check the version and the source state. A conflict returns 409 and writes no history. Service dependencies are private attributes. Entities use public attributes to describe data; encapsulation in code is not decided here. Entity attribute tables give the matching ERD-01 column (FigJam "ERD-01 CampusBorrow 3NF UUID", #46, read 22 November 2026); id types follow E-01 and are not repeated in the tables. Every difference is listed in [Open points vs ERD-01](#open-points-vs-erd-01).

## C1 — AuthService (CMP-01)

Responsibility: authenticate and issue sessions. It does not manage the catalogue or resource operations. Sources: ADR-002, ADR-003 (Accepted), SRS UC-01, FR-01, BR-06/07/10, NFR-04/05.

| #   | Attribute | Type           | Visibility | Constraint                                                          | Description                                |
| --- | --------- | -------------- | ---------- | ------------------------------------------------------------------- | ------------------------------------------ |
| 1   | prisma    | PrismaService  | private    | Injected; no session kept in memory                                 | Writes `revoked_tokens` at logout          |
| 2   | clock     | Clock          | private    | Server time                                                         | Computes the 24-hour expiry                |
| 3   | accounts  | AccountService | private    | CMP-02 export; AuthModule never reads `accounts` directly (ADR-002) | Reads the account, hash and `tokenVersion` |

| #   | Operation | Parameters / return                         | Visibility | Description                                                                                                                                                                                                                                                                                                             |
| --- | --------- | ------------------------------------------- | ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | login     | identifier:string, password:string → Result | public     | Normalises the identifier (BR-06) and reads the account through `AccountService.findByIdentifier(identifier)`. Never trims the password. Checks that the account is active and the hash matches. Issues an HS256 JWT with `sub`, `jti`, `tv`, `iat`, `exp` and the cookie (ADR-003). No credential in the body or logs. |
| 2   | logout    | cookie:string → Result                      | public     | Inserts the `jti` of the current token into `revoked_tokens` (`id` = `jti`, `account_id`, `expires_at` = token `exp`) and clears the cookie. The account's other tokens stay valid (FR-01-02, ADR-003).                                                                                                                 |

Constraints: a wrong credential or an inactive account issues no session. A JWT signing failure never returns success. Passwords are hashed with bcrypt cost 12 over `base64(SHA-256(password in UTF-8))`. When the account does not exist, a dummy bcrypt comparison still runs and the same generic error is returned. The cookie is HttpOnly, Secure, SameSite=Lax, Path=/, Max-Age 24 hours. There is no refresh token or remember-me. Planned PA4 checks: a 64-character Vietnamese password that differs only after byte 72; rejection exactly at expiry; no raw credential in the database or logs.

## C2 — EquipmentRequestService (CMP-04)

Responsibility: accept and decide requests, change the pickup, cancel, record handover, return and expiry, list overdue loans, and keep reservation and loan consistent. Sources: UC-10 – 16; FR-03-01 – 15, FR-04-01 – 06, BR-01/04/05/13.

| #   | Attribute | Type           | Visibility | Constraint                                                      | Description                               |
| --- | --------- | -------------- | ---------- | --------------------------------------------------------------- | ----------------------------------------- |
| 1   | prisma    | PrismaService  | private    | Prisma READ COMMITTED; lock the `resources` row first (ADR-004) | Current state, reservation                |
| 2   | clock     | Clock          | private    | Never trusts client time                                        | Pickup and expiry                         |
| 3   | history   | HistoryService | private    | Same transaction                                                | Decision, handover, expiry events         |
| 4   | accounts  | AccountService | private    | CMP-02 export (ADR-002)                                         | Checks the borrower is active at handover |

| #   | Operation    | Parameters / return                                                                  | Visibility | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| --- | ------------ | ------------------------------------------------------------------------------------ | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | submit       | input:RequestInput, actor:Principal → Result                                         | public     | Borrower only (UC-10). Takes `borrowerId` from the session. Requires a purpose that is not blank and `now < proposedPickupAt < returnDueAt`. Locks the `resources` row, calls `expireIfDue(resourceId, tx)`, then requires a Visible, In service item with no reservation or loan and no active request (Pending, Approved or On loan) of this Borrower for it. Saves Pending without a reservation and appends EQ_REQUEST_SUBMITTED. Pending requests of other Borrowers do not block it (FR-03-01 – 03).                                                                                                                                               |
| 2   | decide       | requestId:Id, decision:Decision, expectedVersion:integer, actor:Principal → Result   | public     | RM or Admin. Locks the `resources` row; on approval it first calls `expireIfDue(resourceId, tx)` (ADR-005). The request is Pending and the resource is eligible. Approve checks that the confirmed pickup is in the future and before the return due time, reserves the item exclusively, rejects every competing Pending request and appends history, all in one transaction. Reject requires a reason of 1 – 500 characters after trimming (FR-03-07).                                                                                                                                                                                                 |
| 3   | handover     | requestId:Id, actor:Principal → Result                                               | public     | RM or Admin. Locks the `resources` row, first calls `expireIfDue(resourceId, tx)` (ADR-005), then rechecks that the request is Approved with the right reservation, the borrower is active and the item is In service; requires `confirmedPickupAt <= now < expiry`; converts the reservation to a loan atomically.                                                                                                                                                                                                                                                                                                                                      |
| 4   | expireIfDue  | resourceId:Id, tx:Tx → Result                                                        | public     | Called inside the transaction that already locks `resources` (ADR-005) and by ExpiryJob. Applies only to Approved, uncollected requests past the cut-off; cancels and releases that reservation and writes a system history event. Never releases a loan already handed over.                                                                                                                                                                                                                                                                                                                                                                            |
| 5   | changePickup | requestId:Id, newPickupAt:Instant, expectedVersion:integer, actor:Principal → Result | public     | RM only (UC-12). Locks the `resources` row, calls `expireIfDue(resourceId, tx)`, then requires Approved, uncollected, `now < expiry` and `now < newPickupAt < returnDueAt`. Keeps the reservation and the return deadline; expiry is recomputed. Appends PICKUP_CHANGED with the old and new pickup. Never revives an expired request.                                                                                                                                                                                                                                                                                                                   |
| 6   | recordReturn | requestId:Id, actor:Principal → Result                                               | public     | RM or Admin (UC-14). Locks the `resources` row and requires a recorded handover and no return (ON_LOAN). Writes `returnedAt` and `returnedBy` from the server, sets RETURNED, clears only this occupancy and appends RETURN_RECORDED. An inactive borrower or a Hidden or Out of service item does not block it, and those flags are kept. A repeated return is refused without a second event.                                                                                                                                                                                                                                                          |
| 7   | cancel       | requestId:Id, reason:string, actor:Principal → Result                                | public     | UC-15. Locks the `resources` row and calls `expireIfDue(resourceId, tx)`. The owner may cancel a Pending or Approved, uncollected request (cause BORROWER). An RM or Admin may cancel only an Approved, uncollected request whose item is damaged or Out of service (cause STAFF_OUT_OF_SERVICE); this staff path is Should (FR-03-11). If it is deferred, the item stays Out of service, handover is blocked, and Borrower cancellation or normal expiry releases the reservation (PA2 v2 §5.1.12). The reason has 1 – 500 characters after trimming. Releases only this reservation, never reopens rejected requests and appends EQ_REQUEST_CANCELLED. |
| 8   | listOverdue  | actor:Principal → Result                                                             | public     | RM or Admin (UC-16); read only, writes no history. Returns the loans with a recorded handover, no recorded return and `now > returnDueAt`; equality is not overdue. Shows request, item, Borrower, return deadline and status. A failed read is reported, never shown as an empty list. A Borrower sees overdue only on their own requests (UC-21).                                                                                                                                                                                                                                                                                                      |

Expiry on access (proposed): when `expireIfDue` finds a due expiry during handover, changePickup or cancel, the transaction commits the expiry (CANCELLED, SYSTEM_EXPIRY, history event) and the operation is refused with 409, so refusing it does not roll back the expiry (ADR-005, BR-04). In submit and decide, a due expiry of another request releases the item first and the operation continues with the current state; a later business refusal keeps that expiry. If the transaction itself fails, the next access or the sweep applies the expiry again. An inactive borrower does not by itself block approval. A Hidden item does not by itself block handover. Any failure must roll back state, reservation and history together and never return a false success. Planned checks: concurrent duplicate submissions create one request; approval after a due expiry on the same item; two approvals produce one winner; expiry racing a handover; early handover and exactly-at-expiry handover are rejected.

Responsibility: show the room schedule, create Pending bookings, decide and cancel them, and void an erroneous approval for CO-04. Sources: UC-17/18/19/20/22, FR-05/06/07, BR-01/03/05/12/13/19/20.

| 2   | timetable | TimetableService | private    | Configured Periods                    | Derives the time interval                           |
| 3   | history   | HistoryService   | private    | Same transaction                      | Records actor and action                            |
| 4   | clock     | Clock            | private    | Server time                           | Checks that the start is in the future              |

| 1   | submit       | input:BookingInput, actor:Principal → Result                                       | public     | Borrower. Takes `borrowerId` from the session. Checks the room is Visible and In service, the interval is in the future, the purpose is present, headcount is an integer from 1 to capacity, and no Approved booking overlaps. Saves Pending; the room is not held.                                                                                                                                                                  |
| 2   | decide       | bookingId:Id, decision:Decision, expectedVersion:integer, actor:Principal → Result | public     | RM or Admin with unit-wide access (BR-01). Rechecks Pending, `expectedVersion` and eligibility. The database exclusion constraint blocks an overlapping approval; a violation (SQLSTATE 23P01) or a stale version rolls back, returns 409 and leaves the booking PENDING (FR-07-03, FR-07-04). The returned fields are listed below the table.                                                                                                   |
| 4   | cancel       | bookingId:Id, reason:string (optional), actor:Principal → Result                   | public     | The owner only (UC-20). Requires Pending or Approved and `now < startAt`. A terminal or already started booking is refused without a second event.    |
| 5   | voidApproval | bookingId:Id, expectedVersion:integer, tx:Tx → Result                              | public     | CO-04 only; called by CorrectionService inside its transaction and not exposed by the controller. A conditional update `WHERE status = APPROVED AND version = ?` that also requires `now < startAt` sets CANCELLED and releases the interval once (ADR-004); 0 rows returns 409. Schedule visibility (FR-05-06, BR-19, PA2 v2): on the room schedule an RM or Admin sees, for each Approved booking, the requester's display name, purpose and headcount together with the reserved interval. A Borrower sees other Borrowers' bookings only as occupied intervals, without identity, purpose or headcount; access to their own booking details follows ownership. `getSchedule` realises this rule. PA2 v2 removed the "assigned scope" wording from FR-07 (BR-01), so no assignment entity is added. Planned checks: competing Pending bookings are allowed; two approved bookings never overlap; adjacent half-open intervals are allowed; a forged `borrowerId` from the client is ignored.

Schedule fields, from PA2 v2 (S07 is not one of the six screens specified in #56):

| Field                                               | Visible to  | Source             |
| --------------------------------------------------- | ----------- | ------------------ |
| Room name, capacity, operational status             | All roles   | FR-05-04           |
| Date                                                | All roles   | FR-05-01           |
| Periods P1 – P8 with start and end                  | All roles   | FR-05-05, BR-03    |
| Approved intervals (start, end), ascending by start | All roles   | FR-05-02, FR-05-03 |
| Requester display name, purpose, headcount          | RM or Admin | FR-05-06           |

The date defaults to today in UTC+7 before the call (FR-05-01). Free periods and breaks are derived from the Periods and the Approved intervals; an interval that spans a break occupies the break as well (AC-05-05). No Approved interval means an empty list, and a failed read is reported as an error, never as an empty schedule (UC-17 A2, E2). An Out of service room can still be viewed (UC-17 E3), but the internal Out of service reason is not returned (BR-19). Mockup S07s also shows the request ID; FR-05-06 does not list it, so it is not returned unless the requirement changes (BR-19).

## C4 — HistoryService (CMP-06)

Responsibility: store the audit trail and read it according to permission. Sources: SRS F08, BR-19, UC-21. It never calls business services back to write an event.

| #   | Attribute | Type          | Visibility | Constraint                                                          | Description                       |
| --- | --------- | ------------- | ---------- | ------------------------------------------------------------------- | --------------------------------- |
| 1   | prisma    | PrismaService | private    | Uses the caller's `tx` and never commits itself (ADR-002, Accepted) | History joins the atomic mutation |

| #   | Operation   | Parameters / return                | Visibility | Description                                                                                                                                                                                                                          |
| --- | ----------- | ---------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | append      | event:HistoryEvent, tx:Tx → Result | public     | Writes eventType, actorId (NULL = SYSTEM), actorRole, targetType and targetId, fromState and toState, reason, details and occurredAt. Internal maintenance reasons are never exposed to a Borrower. Planned checks: an audit failure rolls back the business change; another Borrower's access is denied and reveals no credential.

## C5 — CorrectionService (CMP-07)

Responsibility: apply the controlled administrative corrections CO-01 – CO-04 of BR-20 (PA2 v2) and nothing else. Sources: UC-22, FR-09-09 – FR-09-12 (**Should**), BR-20, ADR-004, ADR-005. `CorrectionController` exposes the same `correct` operation (CD-01).

| --- | --------- | ----------------------- | ---------- | --------------------------------------------------------------- | ------------------------------------------------------------- |
| 1   | prisma    | PrismaService           | private    | Prisma READ COMMITTED; lock the `resources` row first (ADR-004) | Current state, occupancy, `state_corrections`                 |
| 2   | history   | HistoryService          | private    | Same transaction                                                | Appends the `STATE_CORRECTED` correction event                |
| 3   | accounts  | AccountService          | private    | CMP-02 export (ADR-002)                                         | Checks the target account still has the Borrower role (CO-02) |
| 4   | requests  | EquipmentRequestService | private    | CMP-04 export                                                   | `expireIfDue` in CO-01 (ADR-005)                              |
| 5   | bookings  | RoomBookingService      | private    | CMP-05 export                                                   | `voidApproval` in CO-04 (ADR-004)                             |

| #   | Operation | Parameters / return                             | Visibility | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --- | --------- | ----------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | correct   | input:CorrectionInput, actor:Principal → Result | public     | Active Admin only; the account status and role are read from the database. `input` carries `operationCode` (one of CO_01 – CO_04), `targetId`, the corrected time for CO-03, `reason`, `expectedVersion` and `confirmed`. The reason must be 1 – 500 characters after trimming. With `confirmed = false` it runs every check and returns the before/after preview without writing. With `confirmed = true` it locks, rechecks the current state and `expectedVersion`, applies the update, inserts one StateCorrection and appends one `STATE_CORRECTED` event, all in one transaction. Any failed check rejects the whole operation. |

Original events are preserved: a correction never deletes or rewrites history, and each corrected effective value stays traceable to the original event through the StateCorrection and `STATE_CORRECTED` records. Every time check uses `Clock` (CMP-09). A stale version or a changed state returns 409 with no partial change (ADR-004).

| ----- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CO-01 | EquipmentRequest | Void erroneous handover. ON_LOAN → APPROVED if the original reservation has not expired; otherwise apply the normal expiry outcome (CANCELLED, `SYSTEM_EXPIRY`) and leave no active reservation. `confirmedPickupAt` and `returnDueAt` are preserved. The existing capped expiry `min(confirmedPickupAt + 24 h, returnDueAt)` is recomputed; an expired reservation is never revived. Any immediate expiry is part of the same consistent outcome and audit trail. | No effective return exists. Staff confirm the item never left the store. No conflicting occupancy exists on the item.                                                                                                                                                                                     |
| CO-02 | EquipmentRequest | Void erroneous return. RETURNED → ON_LOAN. Overdue is derived from the unchanged `returnDueAt`.                                                                                                                                                                                                                                                                                                                                                                    | Staff confirm the return was recorded in error and the item remains with the Borrower. Rejected if a later reservation or loan exists for the item. Occupancy is rechecked atomically. The target account must still have the Borrower role; an inactive status alone does not erase an outstanding loan. |
| CO-03 | EquipmentRequest | Correct a recorded event time: the effective `handedOverAt` or `returnedAt`. Lifecycle state, original audit evidence, `confirmedPickupAt` and `returnDueAt` are unchanged.                                                                                                                                                                                                                                                                                        | Only an existing event can be corrected. Requires approval (`decidedAt`) ≤ handover ≤ now; where a return exists, handover ≤ return ≤ now. A corrected handover must fall within the pickup window applicable to that event. Excluded: confirmed-pickup edits (UC-12), account administration (UC-04), ordinary catalog status changes (UC-09), and revival of Rejected, Cancelled or expired requests. A correction must not fabricate a physical return or delete historical evidence. Unsupported and stale operations are rejected without partial changes. If FR-09-09 – FR-09-12 (Should) are deferred, the correction mutation interface and API are disabled.

Under ADR-005, CO-01 calls `EquipmentRequestService.expireIfDue(resourceId, tx)` inside its transaction, and CO-04 calls `RoomBookingService.voidApproval(bookingId, expectedVersion, tx)`; CD-01 draws both dependencies. Planned checks: CO-01 on an already expired reservation leaves the request CANCELLED with no active reservation; CO-02 with a later loan is rejected; CO-02 for an account that is no longer a Borrower is rejected; CO-03 outside the pickup window is rejected; CO-04 after the booking start is rejected; a reason of only spaces or of 501 characters is rejected; a stale `expectedVersion` returns 409 and writes nothing.

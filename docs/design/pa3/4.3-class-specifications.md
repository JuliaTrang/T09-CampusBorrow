# 4.3 Class Specifications (#53)

Eight key classes from [CD-01 and CD-02](4.2-class-diagram.md). All signatures and types are **proposals**, not approved API or code; the open points in the [README](README.md) apply to every class. `Resource` is an abstract class with `Equipment` and `Room` as subclasses (kickoff glossary); no other class has a superclass. Following ADR-004, `EquipmentRequest` and `RoomBooking` have an integer `version`. Updates check the version and the source state. A conflict returns 409 and writes no history. Service dependencies are private attributes. Entities use public attributes to describe data; encapsulation in code is not decided here.

## C1 — AuthService (CMP-01)

Responsibility: authenticate and issue sessions. It does not manage the catalogue or resource operations. Sources: ADR-003 (Accepted), SRS UC-01, FR-01, BR-06/07/10, NFR-04/05.

| #   | Attribute | Type          | Visibility | Constraint                          | Description                          |
| --- | --------- | ------------- | ---------- | ----------------------------------- | ------------------------------------ |
| 1   | prisma    | PrismaService | private    | Injected; no session kept in memory | Reads the account and `tokenVersion` |
| 2   | clock     | Clock         | private    | Server time                         | Computes the 24-hour expiry          |

| #   | Operation | Parameters / return                         | Visibility | Description                                                                                                                                                                                                                                 |
| --- | --------- | ------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | login     | identifier:string, password:string → Result | public     | Normalises the identifier (BR-06). Never trims the password. Checks that the account is active and the hash matches. Issues an HS256 JWT with `sub`, `jti`, `tv`, `iat`, `exp` and the cookie (ADR-003). No credential in the body or logs. |
| 2   | logout    | cookie:string → Result                      | public     | Inserts the `jti` of the current token into `revoked_tokens` (`id` = `jti`, `account_id`, `expires_at` = token `exp`) and clears the cookie. The account's other tokens stay valid (FR-01-02, ADR-003).                                     |

Constraints: a wrong credential or an inactive account issues no session. A JWT signing failure never returns success. Passwords are hashed with bcrypt cost 12 over `base64(SHA-256(password in UTF-8))`. When the account does not exist, a dummy bcrypt comparison still runs and the same generic error is returned. The cookie is HttpOnly, Secure, SameSite=Lax, Path=/, Max-Age 24 hours. There is no refresh token or remember-me. Planned PA4 checks: a 64-character Vietnamese password that differs only after byte 72; rejection exactly at expiry; no raw credential in the database or logs.

## C2 — SessionGuard (CMP-01)

Responsibility: check the current session on every protected call. `RolesGuard` checks the role from the database; ownership is checked in the services.

| #   | Attribute | Type          | Visibility | Constraint                             | Description                                              |
| --- | --------- | ------------- | ---------- | -------------------------------------- | -------------------------------------------------------- |
| 1   | prisma    | PrismaService | private    | No permission cache in function memory | Reads the Account and looks up `jti` in `revoked_tokens` |
| 2   | clock     | Clock         | private    | Server time                            | Compares expiry                                          |

| #   | Operation   | Parameters / return               | Visibility | Description                                                                                                                                                                                            |
| --- | ----------- | --------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | canActivate | cookie:string → Principal or deny | public     | Verifies the JWT signature and `exp` using Clock. Requires an active account, `tv` equal to `Account.tokenVersion`, and `jti` absent from the denylist. The Principal uses the role from the database. |

Constraints: 401 when the token or session is invalid or the account is inactive (ADR-003); 403 belongs to `RolesGuard` and ownership checks. Checking only the JWT signature is not enough. Planned checks: logging out one session does not affect another; deactivation, role change and reset revoke every session; reactivation does not restore old sessions.

## C3 — EquipmentRequestService (CMP-04)

Responsibility: decide requests, record handover and expiry, and keep reservation and loan consistent. Sources: UC-11, UC-13; FR-03-04 – 15, FR-04-01/02, BR-01/04/05/13.

| #   | Attribute | Type           | Visibility | Constraint                                                      | Description                       |
| --- | --------- | -------------- | ---------- | --------------------------------------------------------------- | --------------------------------- |
| 1   | prisma    | PrismaService  | private    | Prisma READ COMMITTED; lock the `resources` row first (ADR-004) | Current state, reservation        |
| 2   | clock     | Clock          | private    | Never trusts client time                                        | Pickup and expiry                 |
| 3   | history   | HistoryService | private    | Same transaction                                                | Decision, handover, expiry events |

| #   | Operation   | Parameters / return                                                                | Visibility | Description                                                                                                                                                                                                                                                                                                                     |
| --- | ----------- | ---------------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | decide      | requestId:Id, decision:Decision, expectedVersion:integer, actor:Principal → Result | public     | RM or Admin. The request is Pending and the resource is eligible. Approve checks that the confirmed pickup is in the future and before the return due time, reserves the item exclusively, rejects every competing Pending request and appends history, all in one transaction. Reject requires a reason of 1 – 500 characters. |
| 2   | handover    | requestId:Id, actor:Principal → Result                                             | public     | RM or Admin. Locks and rechecks that the request is Approved with the right reservation, the borrower is active and the item is In service; requires `confirmedPickupAt <= now < expiry`; converts the reservation to a loan atomically.                                                                                        |
| 3   | expireIfDue | resourceId:Id, tx:Tx → Result                                                      | public     | Called inside the transaction that already locks `resources` (ADR-005, Proposed) and by ExpiryJob. Applies only to Approved, uncollected requests past the cut-off; cancels and releases that reservation and writes a system history event. Never releases a loan already handed over.                                         |

Open points: cancel, edit and return operations (UC-12, 14, 15) are added when the final version is built; the three operations above are not the whole of CMP-04. An inactive borrower does not by itself block approval. A Hidden item does not by itself block handover. Any failure must roll back state, reservation and history together and never return a false success. Planned checks: two approvals produce one winner; expiry racing a handover; early handover and exactly-at-expiry handover are rejected.

## C4 — RoomBookingService (CMP-05)

Responsibility: create Pending bookings and decide them. Sources: UC-18/19, FR-06/07, BR-01/03/05/12/13.

| #   | Attribute | Type             | Visibility | Constraint                            | Description                            |
| --- | --------- | ---------------- | ---------- | ------------------------------------- | -------------------------------------- |
| 1   | prisma    | PrismaService    | private    | GiST exclusion for APPROVED (ADR-004) | Blocks overlapping approvals           |
| 2   | timetable | TimetableService | private    | Configured Periods                    | Derives the time interval              |
| 3   | history   | HistoryService   | private    | Same transaction                      | Records actor and action               |
| 4   | clock     | Clock            | private    | Server time                           | Checks that the start is in the future |

| #   | Operation | Parameters / return                                                                | Visibility | Description                                                                                                                                                                                                                                                         |
| --- | --------- | ---------------------------------------------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | submit    | input:BookingInput, actor:Principal → Result                                       | public     | Borrower. Takes `borrowerId` from the session. Checks the room is Visible and In service, the interval is in the future, the purpose is present, headcount is an integer from 1 to capacity, and no Approved booking overlaps. Saves Pending; the room is not held. |
| 2   | decide    | bookingId:Id, decision:Decision, expectedVersion:integer, actor:Principal → Result | public     | RM or Admin with unit-wide access (BR-01). Rechecks Pending and eligibility. The database exclusion constraint blocks an overlapping approval. Reject requires a reason of 1 – 500 characters. Rolls back on error.                                                 |

Open point (TODO-SRS): FR-07 in the current PA2 file still contains an "assigned scope" phrase that conflicts with BR-01 and the change log; the baseline is confirmed in #50, and no assignment entity is added. Planned checks: competing Pending bookings are allowed; two approved bookings never overlap; adjacent half-open intervals are allowed; a forged `borrowerId` from the client is ignored.

## C5 — TimetableService (CMP-05)

Responsibility: validate Periods and derive the interval. It never decides whether to approve a booking. Sources: UC-18, FR-06-01/02, BR-03.

| #   | Attribute | Type          | Visibility | Constraint                    | Description                       |
| --- | --------- | ------------- | ---------- | ----------------------------- | --------------------------------- |
| 1   | prisma    | PrismaService | private    | Periods table (schema in #49) | Fixed P1 – P8, seeded data (C-08) |

| #   | Operation      | Parameters / return                                                | Visibility | Description                                                                                                                                                                                       |
| --- | -------------- | ------------------------------------------------------------------ | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | deriveInterval | bookingDate:Date, firstPeriod:string, lastPeriod:string → Interval | public     | One date. `firstPeriod` and `lastPeriod` are valid codes P1 – P8 in the same DaySession. Derives start and end and keeps any break between them. Rejects a break-only or cross-session selection. |

Period is a fixed table of 8 rows (BR-03, C-08). Period times follow SRS UC-18 (07:30 – 11:00, 13:30 – 17:00, two breaks); the schema and seed data follow #49. Planned checks: invalid codes; P4 – P5 across noon; break-only selections are rejected; two periods around a break keep the whole interval.

## C6 — HistoryService (CMP-06)

Responsibility: store the audit trail and read it according to permission. Sources: SRS F08, BR-19, UC-21. It never calls business services back to write an event.

| #   | Attribute | Type          | Visibility | Constraint                                      | Description                       |
| --- | --------- | ------------- | ---------- | ----------------------------------------------- | --------------------------------- |
| 1   | prisma    | PrismaService | private    | Never commits separately when a caller has a tx | History joins the atomic mutation |

| #   | Operation   | Parameters / return                | Visibility | Description                                                                                                                                                                                                                          |
| --- | ----------- | ---------------------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | append      | event:HistoryEvent, tx:Tx → Result | public     | Writes eventType, actorId (NULL = SYSTEM), actorRole, targetType and targetId, fromState and toState, reason, details and occurredAt. Never writes a password or token. If it fails, the mutation in the same transaction must fail. |
| 2   | listVisible | actor:Principal, query → Result    | public     | A Borrower sees only their own history, with internal information filtered out. An RM or Admin sees history according to current permission. Open point TODO-CMP: ownership queries through CMP-09.                                  |

Constraints: a correction never deletes or rewrites history. Internal maintenance reasons are never exposed to a Borrower. Planned checks: an audit failure rolls back the business change; another Borrower's access is denied and reveals no credential.

## C7 — EquipmentRequest (CMP-04, entity)

Responsibility: the data of one request lifecycle for one equipment item. A Reservation is the state APPROVED and a Loan is the state ON_LOAN; neither is a separate entity. Names and enumerations follow the kickoff glossary of 18 November; multiplicities follow DM-01 (#40, see 4.2). No RM owner is assigned.

| #   | Attribute                             | Type                                 | Visibility | Constraint                                                     | Description                            |
| --- | ------------------------------------- | ------------------------------------ | ---------- | -------------------------------------------------------------- | -------------------------------------- |
| 1   | id, borrowerId, resourceId            | Id                                   | public     | FK to accounts and resources                                   | One Borrower, one item                 |
| 2   | purpose                               | string                               | public     | Required                                                       | Purpose of the loan                    |
| 3   | status                                | EquipmentRequestStatus               | public     | PENDING, APPROVED, REJECTED, CANCELLED, ON_LOAN, RETURNED      | Reservation = APPROVED, Loan = ON_LOAN |
| 4   | proposedPickupAt, confirmedPickupAt   | Instant nullable                     | public     | `confirmedPickupAt` is set when APPROVED; before `returnDueAt` | Proposed and confirmed pickup time     |
| 5   | returnDueAt                           | Instant                              | public     | Not changed by a pickup edit                                   | Return deadline                        |
| 6   | decidedBy, decidedAt, decisionReason  | Id, Instant, string                  | public     | Reject: reason of 1 – 500 characters                           | The RM or Admin decision               |
| 7   | handedOverAt, handedOverBy            | Instant, Id (nullable)               | public     | Only when ON_LOAN                                              | Evidence of handover                   |
| 8   | returnedAt, returnedBy                | Instant, Id (nullable)               | public     | RETURNED only after `handedOverAt`                             | Evidence of return                     |
| 9   | cancellationCause, cancellationReason | CancellationCause, string (nullable) | public     | BORROWER, STAFF_OUT_OF_SERVICE, SYSTEM_EXPIRY                  | Why the request was cancelled          |
| 10  | version                               | integer                              | public     | Incremented on update (ADR-004)                                | Prevents stale writes                  |

| #   | Operation       | Parameters / return     | Visibility | Description                                                                                                                                          |
| --- | --------------- | ----------------------- | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | effectiveExpiry | no parameters → Instant | public     | `min(confirmedPickupAt + 24 h, returnDueAt)`. Only for an Approved request with an appointment. Expiry and Overdue are never stored in the database. |

Constraints: a request is expired exactly at the equality `now = expiry`. After handover the pickup expiry no longer applies. Overdue is derived from ON_LOAN and `now > returnDueAt`. Planned checks: short and same-day loans; a pickup edit never revives an expired request.

## C8 — RoomBooking (CMP-05, entity)

Responsibility: the data of one request for one room on one date. Names follow the kickoff glossary; multiplicities follow DM-01 (#40, see 4.2).

| #   | Attribute                            | Type                 | Visibility | Constraint                                            | Description                                 |
| --- | ------------------------------------ | -------------------- | ---------- | ----------------------------------------------------- | ------------------------------------------- |
| 1   | id, borrowerId, resourceId           | Id                   | public     | FK to accounts and resources (type ROOM)              | The Borrower comes from the session         |
| 2   | status                               | RoomBookingStatus    | public     | PENDING, APPROVED, REJECTED, CANCELLED                | A Pending booking does not hold the room    |
| 3   | bookingDate, firstPeriod, lastPeriod | Date, string, string | public     | Same DaySession; codes P1 – P8                        | Refers to `Period.code`                     |
| 4   | startAt, endAt                       | Instant              | public     | start < end; derived from the periods; `[start, end)` | Never an arbitrary interval from the client |
| 5   | headcount, purpose                   | integer, string      | public     | 1 to capacity; purpose not blank                      | Business input                              |
| 6   | decidedBy, decidedAt, decisionReason | Id, Instant, string  | public     | Reject: reason of 1 – 500 characters                  | The RM or Admin decision                    |
| 7   | cancellationReason                   | string (nullable)    | public     | Set when CANCELLED                                    | Why the booking was cancelled               |
| 8   | version                              | integer              | public     | Incremented on update (ADR-004)                       | Prevents stale writes                       |

| #   | Operation               | Parameters / return | Visibility | Description                                                                                                        |
| --- | ----------------------- | ------------------- | ---------- | ------------------------------------------------------------------------------------------------------------------ |
| —   | No operation of its own | —                   | —          | Derivation and validation live in TimetableService; mutations live in RoomBookingService, so no logic is repeated. |

Planned checks: the exact interval for one room and date; an approved overlap is blocked by the constraint; adjacent intervals where one end equals the next start do not overlap. Physical indexes and constraints belong to #49 and #55.

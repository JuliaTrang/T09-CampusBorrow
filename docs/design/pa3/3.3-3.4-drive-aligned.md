# 3.3 Container Diagram and 3.4 Component Diagram

English text for the PA3 merge. Baseline: Trang's [18 November Drive update](https://docs.google.com/document/d/1gGg8x3rT3SiIO70aaPSqNGK-r8pEZVWT/edit), §§2.1, 3.1–3.2 and 3.6. ADR-001–004 are accepted. ADR-005 and ADR-006 are proposed under I-04.

## 3.3 Container Diagram (C4-L2)

Borrowers, Resource Managers, Admins and prospective Borrowers use the CampusBorrow Web App in a browser. A prospective Borrower can register without signing in and registration creates only the Borrower role. The context from §3.2 excludes SSO, payments, timetable integrations and notifications.

| ID     | Container  | Technology and responsibility                                                                                                                                                      |
| ------ | ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CTN-01 | Web App    | React and Vite SPA in TypeScript. Presents responsive screens, mirrors input validation for feedback and displays business time in UTC+7.                                          |
| CTN-02 | API Server | NestJS REST API in TypeScript. Verifies authentication and authorization, validates requests and coordinates domain operations and transactions. Deployed as one modular monolith. |
| CTN-03 | Database   | Supabase PostgreSQL. Persists accounts, token revocations, resources, equipment requests, room bookings and audit history. Enforces concurrency invariants.                        |

Browsers load CTN-01 over HTTPS. CTN-01 sends JSON and the first-party HttpOnly JWT cookie to CTN-02 over HTTPS. CTN-02 accesses CTN-03 via Prisma over SQL/TLS. Cloudflare, regional placement, environment separation, scheduled backup and monitoring belong in DEP-D. Use ADR-001 for the stack and mark the details introduced by ADR-006 as proposed.

## 3.4 Component Diagram (CMP-D)

CTN-02 contains nine NestJS modules. Controllers and guards form the API layer, services handle business decisions, and PrismaService provides data access. Cross-module business calls go through exported services. When a mutation needs data or history from another module, the caller passes its transaction context.

| ID     | Module              | Responsibility                                                                                                                                                                                                                                  |
| ------ | ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CMP-01 | AuthModule          | AuthController/AuthService issue JWTs and revoke individual tokens on logout. SessionGuard checks expiry, account activation, token version and denylist. RolesGuard uses the current database role.                                            |
| CMP-02 | AccountModule       | AccountController/AccountService manage accounts and increment token version in the same transaction as deactivation, role change or reset.                                                                                                     |
| CMP-03 | CatalogModule       | ResourceController/ResourceService handle resources, availability inputs and catalogue edits.                                                                                                                                                   |
| CMP-04 | EquipmentLoanModule | EquipmentRequestController/EquipmentRequestService handle requests, decisions, pickup, loan and expiry. Lock the resources row first. Update reservation and competing requests with their history in the same transaction.                     |
| CMP-05 | RoomBookingModule   | RoomBookingController/RoomBookingService handle booking requests and decisions. TimetableService derives half-open ranges from fixed P1–P8 periods. PostgreSQL rejects overlapping approved bookings and the conflicting request stays pending. |
| CMP-06 | HistoryModule       | HistoryController/HistoryService read authorized history and append business events in the caller's transaction. Record actor or system origin and omit credentials.                                                                            |
| CMP-07 | CorrectionModule    | CorrectionController/CorrectionService coordinate permitted corrections through the affected business services and append history. Confirm remaining correction details against §8.                                                             |
| CMP-08 | SchedulerModule     | ExpiryJob delegates to the equipment expiry logic. The proposed scheduler and delay target are recorded in ADR-005.                                                                                                                             |
| CMP-09 | CommonModule        | PrismaService, Clock and HttpExceptionFilter supply transactions, server time and consistent error mapping. Stale version and applicable constraint conflicts return 409.                                                                       |

CMP-04 and CMP-05 read resource details through CMP-03. CMP-04, CMP-05 and the other modules that write business history use CMP-06. CMP-07 coordinates corrections through CMP-04/CMP-05. CMP-08 calls CMP-04 for expiry. CMP-01 reads the current account through the service exported by CMP-02, and CMP-02 owns the token version (ADR-002, decided for #44 on 21 November; see [3.3-3.4-container-component.md](3.3-3.4-container-component.md) and the updated [CMP-D](../diagrams/CMP-D_component.drawio)).

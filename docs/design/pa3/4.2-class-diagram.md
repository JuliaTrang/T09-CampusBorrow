## Reading the diagrams

- `+` public, `-` private. `Id`, `Instant`, `Tx`, `Principal`, `Decision`, `Result`, `Interval`, `RequestInput`, `BookingInput` and `Schedule` are conceptual types used to read the diagram; they are not DTO or code names.
- `Instant` is a server time stored as `timestamptz` and shown in UTC+7. `Tx` is the Prisma transaction context.
- A solid arrow from a controller to a service means "calls". A dashed arrow between services means "uses". Every module also uses CMP-09 (`PrismaService`, `Clock`); those arrows are not drawn.
- Return messages in the sequence diagrams show data or results. They are not extra operations.

## Classes and operations

| Component                  | Classes                                             | Main operations and scope                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CMP-01 AuthModule          | AuthController, AuthService                         | `login(identifier, password)`, `logout(cookie)`. The controller forwards the call. The JWT carries `jti` and `tv` (ADR-003). The account is read through `AccountService.findByIdentifier` (ADR-002).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| CMP-01 AuthModule          | SessionGuard, RolesGuard                            | `canActivate(cookie)` returns a Principal or denies; it reads the account through `AccountService.findById`. `authorize(principal, allowedRoles)` returns allow or deny.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| CMP-02 AccountModule       | AccountController, AccountService                   | `register(input)` (UC-06, Borrower only), `create(input, actor)` (UC-03), `changeSecurity(accountId, change, actor)` (UC-04/05: status, role, password reset), `findByIdentifier(identifier)`, `findById(accountId, tx?)`. Increments `tokenVersion` itself in the same transaction (ADR-003), so CMP-02 does not depend on CMP-01. BR-11: an Admin cannot deactivate or change the role of their own account, and the last active Admin cannot be removed. BR-08 blocks a role change with outstanding obligations. AuthModule reads accounts only through this exported service (ADR-002).                                                                                                                                              |
| CMP-03 CatalogModule       | ResourceController, ResourceService                 | `search(query, actor)` and `getDetail(resourceId, actor)` (UC-07), `create(input, actor)` and `update(resourceId, input, expectedVersion, actor)` (UC-08), `changeStatus(resourceId, change, expectedVersion, actor)` (UC-09: visibility or operational status), `getEligibility(resourceId, tx)`. A stale `expectedVersion` returns 409 (BR-17). Visibility, operational status and occupancy are three separate concepts.                                                                                                                                                                                                                                                                                                               |
| CMP-04 EquipmentLoanModule | EquipmentRequestController, EquipmentRequestService | `submit(input, actor)`, `decide(requestId, decision, expectedVersion, actor)`, `handover(requestId, actor)`, `changePickup(requestId, newPickupAt, expectedVersion, actor)`, `recordReturn(requestId, actor)`, `cancel(requestId, reason, actor)`, `listOverdue(actor)`, `expireIfDue(resourceId, tx)`, `voidHandover(requestId, expectedVersion, tx)`, `voidReturn(requestId, expectedVersion, tx)`, `correctEventTime(requestId, event, correctedAt, expectedVersion, tx)`. The last three serve CO-01 – CO-03 and have no route. Submission, approval, pickup change, cancellation and handover first call `expireIfDue` in the locked transaction (ADR-005). Handover reads the borrower through `AccountService.findById` (ADR-002). |
| CMP-05 RoomBookingModule   | RoomBookingController, RoomBookingService           | `submit(input, actor)`, `decide(bookingId, decision, expectedVersion, actor)`, `getSchedule(roomId, date, actor)`, `cancel(bookingId, reason, actor)`, `voidApproval(bookingId, expectedVersion, tx)`. `voidApproval` serves CO-04 only and has no route. A Pending booking does not hold the room. The schedule shows staff fields only to an RM or Admin (FR-05-06). The requester's display name comes from `AccountService.findById` (ADR-002).                                                                                                                                                                                                                                                                                       |
| CMP-05 RoomBookingModule   | TimetableService                                    | `deriveInterval(bookingDate, firstPeriod, lastPeriod)` returns an Interval. Periods P1 – P8 are fixed (BR-03, C-08).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| CMP-06 HistoryModule       | HistoryController, HistoryService                   | `listVisible(actor, query)`, `append(event, tx)`. `append` uses the caller's transaction and never commits itself (ADR-002, Accepted). Never stores tokens or passwords.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| CMP-07 CorrectionModule    | CorrectionController, CorrectionService             | `correct(input, actor)`: preview without writing, then apply on confirmation. Corrections CO-01 – CO-04 follow BR-20 (PA2 v2, PA3 §8 item 4) and are Should priority; see 4.3 C5. CO-01 – CO-03 use `EquipmentRequestService.voidHandover`, `voidReturn` and `correctEventTime`; `voidHandover` applies a due expiry through `expireIfDue` (ADR-005). CO-04 uses `RoomBookingService.voidApproval(bookingId, expectedVersion, tx)` (ADR-004). CO-02 checks the Borrower role through `AccountService.findById` (ADR-002).                                                                                                                                                                                                                 |
| CMP-08 SchedulerModule     | ExpiryJob                                           | `run()`. For each item with an overdue pickup it calls `expireIfDue(resourceId, tx)`, the same logic as the endpoints (ADR-005).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| CMP-09 CommonModule        | PrismaService, Clock, HttpExceptionFilter           | `$transaction(work)` (inherited from Prisma), `now()`, `catch(error)`. No repository wrapper is added.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

The remaining controllers expose the same operations as their services, except service-to-service operations (`expireIfDue`, `voidHandover`, `voidReturn`, `correctEventTime`, `voidApproval`, `append`, `getEligibility`, `findByIdentifier`, `findById`). The sequence diagrams draw calls at the service boundary for brevity; a controller lifeline must use the operations declared in CD-01.

## Entities

| Entity                    | Used by   | Main attributes and invariants (kickoff glossary)                                                                                                                                                                                                                                                                              |
| ------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Account                   | CMP-01/02 | username, email, displayName, passwordHash, role, status (AccountStatus), tokenVersion. Exactly one role. Accounts that acted in history are never deleted.                                                                                                                                                                    |
| RevokedToken              | CMP-01    | id (the `jti`), accountId, expiresAt. Created at logout as a denylist entry; it is not a session table. ExpiryJob deletes expired rows (ADR-005).                                                                                                                                                                              |
| Resource, Equipment, Room | CMP-03    | Resource (abstract): code, type, name, location, description, visibility, operationalStatus, outOfServiceReason, version. Room adds capacity.                                                                                                                                                                                  |
| EquipmentRequest          | CMP-04    | borrowerId, resourceId, purpose, proposedPickupAt, confirmedPickupAt, returnDueAt, status, decidedBy, decidedAt, decisionReason, handedOverAt/By, returnedAt/By, cancellationCause, cancellationReason, version. Expiry and Overdue are computed, not stored.                                                                  |
| RoomBooking               | CMP-05    | borrowerId, resourceId, bookingDate, firstPeriod, lastPeriod, startAt, endAt, headcount, purpose, status, decidedBy, decidedAt, decisionReason, cancellationReason, version. A Pending booking creates no reservation. An overlapping approved booking is blocked by the database.                                             |
| Period                    | CMP-05    | code (P1 – P8), session (DaySession), startTime, endTime, seq. A fixed table of 8 rows.                                                                                                                                                                                                                                        |
| HistoryEvent              | CMP-06    | eventType, actorId (NULL = SYSTEM), actorRole, targetType, targetId, resourceId (NULL for account-only events, FR-08-01), fromState, toState, reason, details, occurredAt. Append-only; never contains credentials.                                                                                                            |
| StateCorrection           | CMP-07    | operationCode (CO_01_VOID_HANDOVER, CO_02_VOID_RETURN, CO_03_FIX_EVENT_TIME, CO_04_VOID_ROOM_APPROVAL), adminId, historyEventId (its `STATE_CORRECTED` event), targetType (EQUIPMENT_REQUEST or ROOM_BOOKING only), targetId, before, after, reason, appliedAt. Each correction also creates a HistoryEvent `STATE_CORRECTED`. |

Enumerations are used exactly as in the kickoff: EquipmentRequestStatus (PENDING, APPROVED, REJECTED, CANCELLED, ON_LOAN, RETURNED), RoomBookingStatus (PENDING, APPROVED, REJECTED, CANCELLED), AccountStatus (ACTIVE, INACTIVE) and DaySession (MORNING, AFTERNOON). The state machines (#52) and the CHECK constraints (#49) use the same sets. Expired and Overdue are computed values and are not stored. CD-02 does not draw the kickoff common columns `createdAt` and `updatedAt`; they apply to every table. The attribute lists match the entity tables of 4.3 (C6 – C8).

## Multiplicities (from DM-01 §5)

| Association                                    | Multiplicity                                                    |
| ---------------------------------------------- | --------------------------------------------------------------- |
| Account — RevokedToken                         | 1 — 0..*                                                        |
| Account — EquipmentRequest (borrower)          | 1 — 0..*                                                        |
| Equipment — EquipmentRequest                   | 1 — 0..* (at most one APPROVED or ON_LOAN at once)              |
| Account — RoomBooking (borrower)               | 1 — 0..*                                                        |
| Room — RoomBooking                             | 1 — 0..* (approved intervals never overlap)                     |
| RoomBooking — Period (firstPeriod, lastPeriod) | 0..* — 1, each                                                  |
| Account — HistoryEvent (actor)                 | 0..1 — 0..* (no actor = SYSTEM)                                 |
| HistoryEvent — target                          | exactly one of Account, Resource, EquipmentRequest, RoomBooking |
| Account — StateCorrection (admin)              | 1 — 0..*                                                        |
| StateCorrection — target                       | exactly one EquipmentRequest (CO_01–03) or RoomBooking (CO_04)  |
| StateCorrection — HistoryEvent (primary)       | 0..1 — 1 (`STATE_CORRECTED`)                                    |
| Equipment, Room — Resource                     | complete and disjoint generalisation                            |

Checked on 21 November: every arrow on CD-02 matches this table.

## Open points before the diagram is final

1. DM-01 is merged (PR #62) and [#40](https://github.com/JuliaTrang/T09-CampusBorrow/issues/40) is closed; CD-02 and the 4.3 entity tables follow it.
2. Module dependencies follow ADR-002 (decided for [#44](https://github.com/JuliaTrang/T09-CampusBorrow/issues/44) on 21 November): AuthModule reads accounts through `AccountService`, and `HistoryService.append` uses the caller's transaction. ERD-01 ([#46](https://github.com/JuliaTrang/T09-CampusBorrow/issues/46)) and the Table Specification ([#49](https://github.com/JuliaTrang/T09-CampusBorrow/issues/49)) now contain the target schema used here; the state of each point is in [4.3, Open points vs ERD-01](4.3-class-specifications.md#open-points-vs-erd-01). E-01 is decided: uuid. Still open: E-04 (`id` or `jti` as the column name), E-10 and E-11 (relationship markers in ERD-01) and E-12 (constraint note on the ERD-01 board).
3. Every message in SD-01 – SD-05 uses an operation declared in CD-01, and the use cases match the SRS. The traceability update (#58) uses the same names and codes.
4. Transaction and concurrency design: state, reservation and history change in one transaction; SQL locks and constraints follow ADR-004. The diagrams are not evidence that tests have run.

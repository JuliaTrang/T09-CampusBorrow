# PA3 §3.3 Container Diagram and §3.4 Component Diagram

Owner: Minh (issues #43, #44). Sources: submitted PA2 SRS, ADR-001 on `main`, and the PA3 kickoff glossary (container codes CTN-01–CTN-03, component codes CMP-01–CMP-09). Diagram sources: `docs/design/diagrams/C4-L2_container.drawio` and `docs/design/diagrams/CMP-D_component.drawio`.

## 3.3 Container Diagram (C4-L2)

CampusBorrow has three containers. The technology of each container follows ADR-001. Where each container is hosted is shown in the deployment diagram (DEP-D, §3.5).

| Code   | Container  | Technology                           | Responsibility                                                                                                                                                      |
| ------ | ---------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| CTN-01 | Web App    | React, Vite, TypeScript (SPA)        | User interface for Borrower, Resource Manager and Admin; responsive from 360 to 1920 px (NFR-10). Holds no business rules.                                          |
| CTN-02 | API Server | NestJS (Node.js, TypeScript), Prisma | All business rules and server-side authorization on every protected call (NFR-03); sessions; request and booking lifecycles; history; pickup-expiry job (FR-03-13). |
| CTN-03 | Database   | PostgreSQL on Supabase               | Stores accounts, sessions, resources, requests, bookings and history. Constraints block double reservation and overlapping approved bookings (NFR-09).              |

| From            | To     | Interaction         | Protocol                        |
| --------------- | ------ | ------------------- | ------------------------------- |
| All three roles | CTN-01 | Use the application | HTTPS, web browser              |
| CTN-01          | CTN-02 | Calls the REST API  | JSON over HTTPS, session cookie |
| CTN-02          | CTN-03 | Reads and writes    | SQL over TLS, through Prisma    |

## 3.4 Component Diagram (CMP-D)

The API Server is split into nine NestJS modules. Each module is one component here and one package in the class diagram (§4.2).

| Code   | Component           | Main classes                                                | Use cases                             |
| ------ | ------------------- | ----------------------------------------------------------- | ------------------------------------- |
| CMP-01 | AuthModule          | AuthController, AuthService, SessionGuard, RolesGuard       | UC-01, UC-02                          |
| CMP-02 | AccountModule       | AccountController, AccountService                           | UC-03 – UC-06                         |
| CMP-03 | CatalogModule       | ResourceController, ResourceService                         | UC-07 – UC-09                         |
| CMP-04 | EquipmentLoanModule | EquipmentRequestController, EquipmentRequestService         | UC-10 – UC-16                         |
| CMP-05 | RoomBookingModule   | RoomBookingController, RoomBookingService, TimetableService | UC-17 – UC-20                         |
| CMP-06 | HistoryModule       | HistoryController, HistoryService                           | UC-21; all modules record events here |
| CMP-07 | CorrectionModule    | CorrectionController, CorrectionService                     | UC-22                                 |
| CMP-08 | SchedulerModule     | ExpiryJob                                                   | FR-03-13 (pickup expiry, I-04)        |
| CMP-09 | CommonModule        | PrismaService, Clock (UTC+7), HttpExceptionFilter           | Shared by all modules                 |

Dependencies (A uses B):

| From                            | To     | Why                                                                                    |
| ------------------------------- | ------ | -------------------------------------------------------------------------------------- |
| Every protected route           | CMP-01 | SessionGuard and RolesGuard check session, activation and role first (NFR-03, NFR-05). |
| CMP-02                          | CMP-01 | Deactivation, role change and password reset revoke the account's sessions (BR-10).    |
| CMP-04                          | CMP-03 | Reads item visibility and operational status before request, approval and handover.    |
| CMP-05                          | CMP-03 | Reads room visibility, status and capacity.                                            |
| CMP-07                          | CMP-04 | CO-01 – CO-03 change equipment requests.                                               |
| CMP-07                          | CMP-05 | CO-04 voids an erroneous room approval.                                                |
| CMP-08                          | CMP-04 | The expiry job cancels approved, uncollected requests at their expiry.                 |
| CMP-02 – CMP-05, CMP-07, CMP-08 | CMP-06 | Record history events (BR-19).                                                         |
| Every module                    | CMP-09 | Database access, server time, error mapping.                                           |

Design notes:

- The dependency graph has no cycle. CMP-06 and CMP-09 depend on nothing else, and CMP-01 reads accounts through CMP-09, not through CMP-02.
- Controllers only accept requests and return responses. Business rules live in services, so sequence diagrams (§4.4) call service operations.
- Every time-based decision uses `Clock` on the server, never the client time.
